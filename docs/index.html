FAQ

What is FW Executor?
Personal Windows Roblox executor. Madium-class clean UI, 100% UNC + sUNC surface, auto offsets, manual-map inject. Branding: FW. identifyexecutor returns "FW".
Is it undetected?
No executor is permanently undetected. Hyperion changes weekly. FW uses manual-map + PEB unlink + header wipe as the primary path and refreshes offsets every version. Architecture + update speed is the product — not marketing slogans.
What does Strategy A / B mean?
Strategy A is the primary path: resolve DataModel → ScriptContext → live lua_State, create a persistent child thread, set identity 8, load + pcall. This is what Wave / Madium class tools use for full environment. Strategy B embeds a Luau compiler + VM inside the DLL as a fallback when ScriptContext arm fails.
How do offsets work?
On boot and from Settings → Refresh. Sources: rbxoffsets.com first, then a GitHub mirror. Version-pinned. You don't hand-edit offsets.hpp for normal use.
Does it support sUNC / ScriptBlox hubs?
Yes. Full UNC + sUNC catalog ships with all groups enabled by default (env, identity, closures, metatable, FS, HTTP, encoding, crypt, drawing, instances, scripts, cache, input, debug, signals, websocket, actors, misc). Soft stubs keep hubs alive until Strategy A arms native implementations.
What OS / build is required?
Windows x64. Built with VS2022 (v143). Output: ShivExecutor.exe + ShivExec.dll (keep together). Links d3d11, dxgi, winhttp.
Can I use it on multiple PCs?
